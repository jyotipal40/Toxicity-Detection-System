01 — THE PROJECT

Understanding Toxicity

Online platforms generate enormous amounts of user-generated content every day. Identifying toxic comments manually is difficult, time-consuming, and difficult to scale.

01

What are we solving?

This project develops a machine learning based system for classifying comments as TOXIC or NON-TOXIC.

The system uses Natural Language Processing to transform raw text into numerical features and then applies multiple machine learning algorithms to identify the model that performs best on the toxicity classification task.

◎

Binary Classification

A comment is considered toxic when at least one of the toxicity-related labels in the dataset is present.

TOXIC NON-TOXIC
✦

Primary Objective

Compare different machine learning approaches and select the most suitable model using evaluation metrics that account for the imbalanced nature of the dataset.

02 — DATASET

The Jigsaw Dataset

The project uses the Jigsaw Toxic Comment Classification dataset containing Wikipedia comments annotated for different forms of toxicity.

01

Six Toxicity Labels

The original dataset contains six toxicity-related categories.

02

Binary Target

0 NON-TOXIC
→

The six original labels are combined into one binary target. If any toxicity label is present, the target becomes 1.

Train / Test Split

The dataset is split using stratification so that the class distribution is preserved between training and testing data.

FINAL MODEL

Why Logistic Regression?

Model selection was based on F1 score rather than accuracy because the dataset contains an imbalanced distribution between toxic and non-toxic comments.

Logistic Regression achieved the highest F1 score of 71.49% and a toxic-class recall of 86.23%, making it the selected model for the final system.

PROJECT JOURNEY

Challenges & Learnings

Building the classifier involved several practical challenges in text preprocessing, feature engineering and model evaluation.

01

Class Imbalance

Toxic and non-toxic comments were not evenly distributed. This made accuracy alone insufficient for evaluating the effectiveness of the classifier.

Learning Focus on F1 & Recall
02

Text Representation

Raw comments cannot be directly processed by traditional machine learning algorithms, requiring an effective numerical representation of text.

Learning TF-IDF Feature Engineering
03

Data Leakage

The preprocessing pipeline needed to ensure that information from the test set was not used while fitting the TF-IDF vectorizer.

Learning Split Before Vectorization
04

Model Selection

Different classifiers showed different strengths across accuracy, precision and recall, making metric-based comparison essential.

Learning Select Using F1 Score
NEXT STEPS

Future Work

The current system provides a classical machine learning baseline for toxicity detection. Several improvements can make the system more robust and practical.

01

Deep Learning Models

Explore transformer-based architectures such as BERT for richer contextual understanding.

02

Multi-Label Classification

Predict individual categories such as toxic, obscene, threat, insult and identity hate instead of using a single binary target.

03

Improved Context Understanding

Investigate approaches that better handle sarcasm, slang, spelling variations and context-dependent language.

04

Real-Time Integration

Integrate the trained model into a practical moderation or content-filtering system.
